# Amazon 图片需求生成器 V3.2.0

这是一个面向亚马逊运营、美工和多语审核人员的本地 Python 桌面程序。它把产品资料、尺寸变体、竞品、关键词、品牌规范和模块规划，转换为可执行的 Excel 图片需求表、所选语言文案（自动中文对照）和最终 JPG 图片。

## V3.2.0 当前使用方式

- 顶部「外观主题」可切换苹果/iOS玻璃拟态、极简瑞士/Notion、Bento卡片网格、新拟态Soft UI。主题随配置自动保存，勾选改为清晰的 ✓，激活菜单不再扩大/缩小页签边距。苹果玻璃效果是原生Tk的浅色分层模拟，不是真正的系统背景模糊。
- 文案工作流现在为「分析上下文 → 卖点与排版审核 → 多语言文案与版本审核 → 接口请求与返回JSON」。模块Prompt和逐图文案Prompt合并在卖点审核页，选择左侧模块自动加载该模块的指令；仍可AI优化当前/全部Prompt。
- 「局部生成 / 重新生成文案」也在卖点审核页，首次未全局生成时即可单独生成一个模块。文案审核页不再放图片重生/蒙版操作；这些操作保留在图片生成页。自查结果框为9行并带滚动条。
- 默认开启「生成文案前AI重建卖点与排版」：每个非白底模块先请求主卖点、本图角度、事实依据、视觉证明和PC/移动端文本位置，再请求文案。每一步的请求/响应在接口页可见，卖点与进度逐模块更新。自动流程保留手工改过的字段及自定义区块；要覆盖手工卖点，请点击「AI重建卖点与排版：当前/全部」。取消自动规划则沿用审核版式。自动规划通常每模块增加一次文案模型请求，失败会显示原因并保留原稿，不偷偷改用本地方案。
- 主卖点、角度、事实依据与场景均可编辑并自动保存。事实依据以分号分隔。AI重建不会把未核实的功能当成保证，仍需人工确认。
- 排版预设去掉仅左右/上下的菜单项，保留独立的主视觉环绕、细节引线、场景杂志、规格对照、卡片矩阵、编号步骤，PC和移动端各有构图。「自定义」及精调窗口允许新增/删除/重命名文案区块、图片场景，拖动或输入百分比位置；区块数量同步两端，位置分别调整。改变文案区块数量后，请重新生成文案。
- 图片页「当前图片Prompt」下新增版本对比：左侧选择历史版本，右侧显示最新结果，点击图片可放大。单张重生、蒙版及再次批量生成均保留旧图；每张返回后立即更新对比，不必等整批结束。旧文件丢失时明确提示，不会覆盖新图。
- 旧配置、素材和API Key不清空；旧文案子页位置会迁移到合并后的正确页面。更新后关闭旧程序，再双击 `run_app.bat`，标题应为 V3.2.0，无需编译。

## V3.1.0 使用方式（其余功能保持兼容）

- 主菜单：API配置 → 产品信息 → 竞品与关键词 → 选择模块 → 文案生成 → 图片生成 → 批量任务与合规。统一蓝白配色、卡片分组和高对比度页签。
- API Key 按供应商及文案/图片用途独立保存。离开 Key 输入框或切换供应商时自动保存，可点击“保存当前供应商 Key”。主用及备用供应商切换时通过接口更新模型；无 Key 或获取失败时保留预设，并在状态栏提示。测试连接仍保留。
- 产品信息新增品牌 Slogan、Logo 缩略图和实际品牌色色块。品牌资料与 Logo 视觉分析进入后续 AI 上下文；Logo 与产品实拍分角色处理。
- 选择模块页合并重复添加、双栏已选列表、拖拽排序、多选删除、轮播数量与模块 Prompt。
- 文案默认只选德语，支持英语和欧洲多种语言的多选，中文必选自动生成。接口同时返回每个目标语言的逐行中文对照；文案审核和历史版本保留。更多语言在“更多欧洲语言”展开。
- 图片预览、逐图 Prompt、风格参考、AI 优化、审核意见和重生集中在一个页签。选择图片后可用“重新生成当前图片”，保留原上下文并附带修改意见；仍支持蒙版局部重生。
- 图片文案语言在图片页下拉选择。每张返回立即更新预览；图片生成只更新 JPG/图片包与审核记录，不自动生成或更新 Excel。
- “单独导出 Excel（不调用 AI）”使用当前已生成内容与已上传素材；也可先导出离线设计需求。Excel 按所选语言生成列，附带“语言与中文对照”工作表。图片或文案再次修改后，请重新点击导出。
- 文案与图片均有暂停、继续和结束任务。暂停保留在途回复并等待继续；结束禁止本轮后续步骤、丢弃迟到回调，不能恢复旧任务。供应商已收到的请求可能继续执行和计费，本地停止不等于远端取消。
- 顶部可直接填写配置名称，支持保存/重命名、另存及下拉切换；原配置、托管图片和历史记录兼容。小窗口下文案、模块和图片审核均可滚动。

Key 仅在本机 `.env` 中保存为 `AMAZON_BRIEF_TEXT_<供应商ID>_API_KEY` / `AMAZON_BRIEF_IMAGE_<供应商ID>_API_KEY`，不会写入产品 JSON、Excel、配置快照或调试日志。旧 `CUNAI_API_KEY` 等仍作为未单独保存时的兼容回退。`.env` 是本机明文配置，请妥善保管，不随图片资源包分享。

双击 `run_app.bat` 启动。升级后关闭旧窗口再打开，标题应显示 V3.1.0，无需编译。以下为历史版本记录；操作说明以本节为准。

默认示例产品为旅行行李箱，但开放式属性和可增删变体适用于其他品类。AI 成图仍须对照真实产品照片人工核验，不能代替上架前的产品一致性、拼写及合规审核。

## V3.0.2 图片参数修复与最终结果模式

- 修复日志中 SudoCode / `gpt-image-2` 的不兼容请求：有产品/风格图或蒙版时使用 `/images/edits` multipart 上传；无图时才用 `/images/generations`。GPT 图片模型不再携带 `response_format=url`；兼容处理返回的 Base64 或 URL。
- 生图不再重复塞入整份竞品内容、全局词库和逐图事实复述；保留产品原始规格、变体、冲突信息、当前文案、用户 Prompt 和版式。压缩派生分析，发送前检查 32,000 字符上限；必要输入过长会报本地错误，不会静默截掉用户文案。完整分析仍可查看和保存。
- 直接要求模型生成含确认德语原文的最终图片（白底首图无文字），取消无字草稿、额外叠字副本和失败占位图。上传的产品图及风格图仍是输入，原文件不删除。
- 单张结果保存后、OCR/质检及下一张请求前发布预览事件；预览区移到导出页顶部，界面事件分批处理。首张结果自动显示，可关闭“跟随最新完成图片”保持正在审核的图片。
- 输出 `final_images/` 和 `final_images.zip`。Excel G 列为生成状态/错误，H 列为最终结果图；F 列仅保留上传的产品输入参考，不生成图片草稿。失败模块无新图，重生失败保留旧结果；不完整 A+ 不生成占位海报。
- 旧配置自动沿用，文字制作统一升级为最终成图。旧输出目录、输入照片、API Key 不删除、不覆盖。重启 `run_app.bat` 后标题显示 V3.0.2，无需编译。

OpenAI Docs 的[图片生成参数](https://developers.openai.com/api/reference/resources/images/methods/generate)与[图片编辑参数](https://developers.openai.com/api/reference/resources/images/methods/edit)用于校对格式。第三方需实际开放所选模型的编辑接口；400/404 不会自动移除产品图重试。以下旧版本变更记录保留历史描述，以本节为准。

## V3.0.1 上下文超时修复

- 修正 CUNAI 504 响应要求等待120秒、程序却在1/2秒后重试的问题；支持响应头日期/秒数及JSON退避提示，兼容524和本机网络超时，保持暂停可用。
- 产品理解逐张上传1280px分析副本并要求简洁回复，不删除或压缩原始产品图。
- 成功分析逐张保存，失败后“分析 / 继续上下文”只续跑未完成部分；强制重建移为独立确认操作。
- 等待提示与原始请求/错误响应同时保留，不再把产品理解失败误标为OCR失败。持续的供应商故障仍需更换视觉模型/供应商或联系其支持。

## V3.0 更新重点

- 默认先把全部录入产品资料及全部产品实拍分批交给支持视觉的文案模型理解；资料、图片或模型变化后自动失效重建，每次后续请求显式附带原始事实及分析结果。
- 新增产品上下文记录页，显示分析 Prompt、回复与图片清单；两处 API 检查器继续显示脱敏后的完整请求/返回参数。
- 每张图（包括每个轮播帧）独立维护文案 Prompt、图片 Prompt；支持 AI 优化当前或批量优化全部，逐项写回原字段并保存优化历史。
- 图片页新增逐帧布局/风格参考图，可追加上传、勾选删除和预览；产品实拍和风格参考严格区分用途。
- 卖点版式页支持 AI 自动生成当前/全部模块的 PC 与移动端版式，并检查文本框边界、重复槽位与文案框相互重叠，保留拖动精调。
- 六语审核新增并排语言对比，默认左德语、右中文，原历史版本对比仍保留。
- 高级导航轮播默认 4 帧，可配置 1–20 帧（程序任务数量范围，不代表 Amazon 上传限制），每帧独立生成、审核和导出。
- 图片请求使用当前逐帧 Prompt 和已确认德语原文，不再由旧的自动 `image_prompt` 覆盖。可选精确本地排字或 AI 直接绘字。
- Excel 增加“V3提示词与上下文”页；轮播每帧单独占行和输出 JPG。沿用 `user_data` 自动保存与图片托管，升级不覆盖用户资料及 `.env`。

完整操作与边界见 [V3.0使用说明.md](V3.0使用说明.md)。

- 新增A+整幅PC/移动端JPG与各章独立图片；Excel新增海报预览、文件链接和分章尺寸，ZIP包含AI原图、德语效果图及海报资源。视频/交互/多图模块输出章节设计参考，不冒充可直接上传的最终模块。

## 关于 ChatGPT/Codex 直连

ChatGPT/Codex 登录用于 Codex 客户端自身的订阅访问，不是可由任意本地 Python 程序复用的通用 API 凭据。官方支持的程序化 OpenAI 调用仍应使用 Platform API Key；本项目不会读取 Codex 登录令牌或浏览器会话。因此，V2.5 采用“供应商 API + 文件化兼容接口”的方式生成文案和图片。

详见 [AI供应商配置指南.md](AI供应商配置指南.md)。

## AI 配置

1. 打开程序的“AI 接入”页，分别从下拉框选择文案供应商和图片供应商。
2. 在对应的密码掩码输入框粘贴 API Key；此时当前会话已可直接使用。
3. 需要下次启动继续使用时点击“保存到项目 .env”；已有 `.env` 也可点击“从 .env 重新载入”。
4. 点击“获取全部模型”，再从模型下拉框选择当前账户可用模型。
5. 点击“测试连接”验证模型列表和调用接口；文案测试会产生极少量 token。
6. 排错时保持“打印脱敏请求/响应JSON”开启；失败后点击“打开API JSON日志”，根据相同 `request_id` 对照请求和响应。
7. 按需设置备用供应商、重试、限流、缓存和费用预估；再启用 AI 文案、AI 图片及质量检查。

文件名必须是项目根目录下的 `.env`，不是 `.env.example` 或 `env`。`.env.example` 只是无密钥示例文件；如果真实 Key 曾写入示例文件，应立即移除并建议到供应商控制台轮换。

CUN.AI 图片预设不硬编码模型名，因为图片能力取决于账户实际可见模型。选择 CUN.AI 后请先点“获取全部模型”，再选择明确支持图片生成的模型；若网关未开放 `/images/generations` 或模型仅支持文本，程序会显示真实接口错误并按配置尝试备用供应商。

需要修改供应商参数时编辑 `amazon_image_brief/resources/ai_providers.json` 并重启程序。快速测试 CUN.AI：

```powershell
python cun_ai_test.py
```

没有 API Key 时，程序仍可生成本地六语基础文案、设计说明和完整 Excel；AI 改写、自查、生图及局部重生需要所选供应商的有效 Key。模型权限、区域、价格和限流以供应商控制台为准。

## 推荐工作流

1. 在“产品与变体”页填写已验证资料，选择站点并上传真实产品白底图。
2. 设置品牌预设；需要时上传 Logo 并提取品牌色。
3. 在“竞品与关键词”页手动录入，或导出模板后填写并导入。
4. 从左侧模块目录多次添加所需模块，在右侧即时核对；到确认页复制、批量删除、排序并填写每个实例的 Prompt。
5. 在“六语文案审核”页生成初稿，执行局部或全局重写、版本对比、状态标记和自查。
6. 在“AI 接入”页测试连接并估算费用；批量 SKU 可加入持久化队列，单项目在“生成与导出”页执行。
7. 在“批量任务与合规”页先运行规则预检；需要时用蒙版局部重生并复核结构相似度、OCR、回译和溢出结果。
8. 美工依据 Excel 的尺寸、设计说明、六语文案和 JPG 参考图制作终稿，并在上传前核对 Seller Central 实时规则。

## 批量项目 JSON 怎么使用

程序的批量队列按“一份 JSON 对应一个 SKU 项目”工作：

1. 先在前 6 个页面完整配置一个 SKU。
2. 到“批量任务与合规”点击“导出批量项目JSON模板”；也可以参考项目根目录的 `批量项目JSON模板.json`。
3. 为每个 SKU 复制一份 JSON，修改 `project_name`、`sku`、`variants`、`product_image_paths`、模块和模型选项。
4. `product_image_paths` 必须是执行批量任务这台电脑可访问的绝对路径。
5. 点击“添加项目JSON（可多选）”，确认队列后点击“开始生成”。

模板中的 `_template_help` 仅供人阅读，程序载入时会自动忽略。首次批量运行建议先用 1 个 SKU、少量模块或关闭 AI 图片试跑，确认费用与输出后再扩大任务。

## 规则库三个按钮怎么使用

- `导入本地规则JSON`：仅在已有团队自定义规则文件时使用；程序会校验 schema 后复制为本机 override 规则。
- `导出规则JSON模板`：导出当前完整规则结构，供团队修改站点、品类、禁用词和尺寸阈值。
- `从HTTPS更新规则`：从可信的 HTTPS JSON 直链下载规则，适合团队把规则文件托管在内部静态地址。普通网页、网盘分享页和 HTTP 地址不能使用。

日常使用不需要操作这三个功能，路径留空时程序自动使用内置规则库。

## 导出图片审核与二次生成

完整生成结束后，第 8 页下方会出现所有模块图片：

1. 在导出页顶部逐张预览最终结果图；上传素材仍在“产品与变体”或逐帧风格参考页预览。
2. 标记“满意”或“不满意-待修改”；不满意项填写具体修改意见，例如“箱体放大 15%，保留轮子结构，背景改为明亮机场候机区”。
3. 使用“按意见整张重生”生成新的完整方案，或“蒙版局部重生”只修改涂抹区域。
4. 多张图片分别填写意见并标记不满意后，点击“批量重生全部不满意”。没有修改意见的项目不会进入批量重生。
5. 新图状态自动变为“待复核”，旧图片不会删除；审核状态和意见会自动刷新到 Excel 与 JSON。

每次完整生成会建立独立时间戳目录：

```text
outputs/时间戳-项目名/
├─ 项目名-图片需求表.xlsx
├─ project.json
├─ briefs.json
├─ preflight_report.json
├─ qa_report.json
├─ final_images/

```

Excel 包含 `项目参数`、`主图`、`高级A+`、`Brand Story`、`品牌旗舰店` 和 `Amazon规则预检`；存在历史文案时还会生成 `文案版本记录`。

## 质量控制选项说明

- `产品结构锁定`：在图片 Prompt 中要求保持真实参考图的箱体轮廓、轮组、拉杆、缝线、Logo 位置、材质和颜色。它是生成约束，不是像素级锁定，也不能代替人工复核。
- `最低相似度(0–100)`：生成后用本地图像特征比较 AI 图与产品参考图；低于阈值时写入警告，但不会自动判定合规或删除图片。场景图背景变化大，通常应比白底图/细节图使用更低阈值。
- `启用结果缓存`：相同供应商、协议、地址、模型、Prompt、画幅、质量、参考图和蒙版再次请求时，直接复用 `.cache/ai` 中结果，节约时间和 API 费用。API Key 不进入缓存键；局部重生会主动绕过缓存。

## 合规与数据边界

- 白底首图必须是主图第 1 张，纯白背景，只展示售卖产品，不添加文案、图标、道具或促销信息。
- 关键词只可自然用于可见文案和对应画面语义，不使用隐藏文字或无关词堆砌。
- 不自动编造尺寸、容量、测试、认证、排名、评分、奖项、保修或竞品比较结论。
- AI 参考图必须对照真实产品图复核外形、颜色、材质、零件和附件。
- 各供应商对参考图、尺寸和异步任务的支持不同；不兼容时保留错误明细，不生成占位图，也不把输入照片冒充生成结果。
- 程序中的尺寸是策划建议；最终以上传时 Seller Central 创建器提示为准。
