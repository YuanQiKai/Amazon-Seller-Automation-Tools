# Amazon 图片需求生成器｜V2.4 需求规格说明

## 1. 产品目标

把运营侧分散的产品、变体、竞品、关键词和品牌资料转化为可审核、可追溯、可由设计师直接执行的多语图片需求。核心交付物是“Excel 需求表 + JPG 参考图片资源 + 项目/Brief JSON”，不是无需复核即可上架的终稿。

## 2. 用户与主流程

- 运营：录入资料、规划模块、配置 AI、生成和修改文案。
- 美工：读取构图目的、PC/移动尺寸、品牌规范和六语文案，制作正式素材。
- 翻译/站点负责人：比较文案版本，复核六语语义、长度和当地表达。
- 审核人：标记审核状态，检查声明证据、商标、图片真实性和站点规则。

流程：产品与变体 → 竞品与关键词 → 双栏模块选择 → 实例确认/排序/Prompt → 六语文案与审核 → AI 配置与费用估算 → 规则预检/批量队列 → 图片生成 → Excel/图片包 → 人工终审。

## 3. 输入模型

### 3.1 通用参数

项目名称、SKU、ASIN、品牌、中英文品名、品类、目标商城、目标人群、定位、型号、通用尺寸、颜色、材质、重量、容量、价格、功能、卖点、包装、维护、保修、认证/测试、禁用声明、产品图和竞品图。

### 3.2 产品变体

用户可新增、复制、修改或删除任意数量的变体。每个变体包含：变体名称、SKU、尺寸、颜色、重量、容量、价格。选中后编辑会在 Enter、焦点离开、切换变体及保存/导出前自动落盘；复制项保留产品属性并添加名称/SKU 副本标识。行李箱默认示例为 20/22/24 寸；所有数值必须来自实测或可核验资料。

### 3.3 品牌预设

品牌语气、视觉风格、字体建议和品牌色采用“预设下拉 + 可手动编辑”。Logo 导入后在本地分析主要像素并排除近白/近黑背景，返回至多 5 个十六进制颜色；用户可继续修改。

### 3.4 竞品、关键词与自定义属性

竞品和关键词支持手动输入、Excel 导入及模板导出。自定义产品属性使用开放式“参数名/参数值”结构。竞品内容只用于策略观察，不复制竞品商标、受版权保护素材或未经证明的比较声明。

## 4. 模块实例模型

模块目录只定义可添加的类型，最终方案由 `ModuleInstance` 列表构成。每次添加都会生成独立实例 ID，允许同一模块使用多次。每个实例包含：

- `instance_id`：项目内唯一标识；
- `module_code` 与所属渠道；
- 独立 Prompt、排序、六语文案、版本历史、审核状态、自查结果和图片路径。

旧 V2 项目若只有模块代码列表，加载时按出现顺序迁移为 `MODULE_CODE__01`、`MODULE_CODE__02` 等唯一实例。后续读写以实例 ID 为主，并兼容读取旧模块代码键值。

### 4.1 主图

默认 9 张，可重复添加、删除和排序。默认类型包括白底首图、颜色尺寸、细节特写、功能展示、使用人群、使用场景、结构分解、核心卖点、维护/保修。白底首图必须排在主图第 1 位且无任何文案。

### 4.2 高级 A+

默认 7 个，可从视频图像轮播、双图片和文本、背景图和文本、视频和文本、单图片和文本、简单轮播、全视频、四图片和文本、完整图片、导航轮播、技术规格、文本、比较表、热点、轮播规则和问答等类型中重复添加。

### 4.3 Brand Story 与品牌旗舰店

同样采用可重复模块实例。模块选择页左侧显示模块库、右侧即时显示全部已选实例；确认页支持添加、复制、多选批量删除、拖拽/按钮排序，并为每个实例保存独立 Prompt。

## 5. AI 供应商与认证

### 5.1 接入边界

本地 Python 程序不读取或复用 ChatGPT/Codex 登录态。程序化调用使用各供应商正式 API Key。API Key 只从进程内临时输入或指定环境变量读取，不写入项目 JSON、Excel、Brief JSON 或源代码。

### 5.2 独立配置

文案与图片可分别选择供应商和模型。普通用户界面只显示供应商/模型下拉框、获取模型和测试连接；协议、Base URL、Endpoint、模型列表地址、Key 环境变量名及附加请求头集中在 `resources/ai_providers.json`，项目文件只保存非敏感选择结果。

### 5.3 预设与自定义

- 文案：OpenAI Responses、OpenAI-compatible Chat Completions，以及 OpenAI、CUN.AI、阿里云、火山、智谱、SiliconFlow、百度和自定义预设。
- 图片：OpenAI Images、常见 URL/b64 图片响应、SiliconFlow 图片结构、DashScope 万相结构，以及 OpenAI、CUN.AI、阿里云、火山、智谱、SiliconFlow 和自定义预设。
- 自定义接口支持可编辑模型/地址/请求头和已实现的兼容响应结构，不承诺适配任意私有请求体；特殊协议需新增适配器。
- CUN.AI 固定使用 `https://www.cun.ai/v1`、`/chat/completions`、`/models`、`CUNAI_API_KEY`，内置回退模型为 `claude-fable-5`；所有参数允许通过供应商 JSON 后续维护。
- CUN.AI 图片预设使用同一 Base URL、Key 与 `/models`，按 OpenAI Compatible `/images/generations` 适配；图片模型不硬编码，用户须选择账户实际返回且支持生图的模型。

### 5.4 连通性、容错与成本

- 文案/图片供应商均可请求模型目录并自动填充当前账户可见模型；文案连接测试额外发送极短对话，确认所选模型的真实调用链。
- 主供应商对临时网络错误按配置重试；仍失败时可分别切换至一个备用文案和备用图片供应商。
- 全局按供应商执行每分钟请求限流；相同请求通过本机内容哈希缓存复用结果，局部重生显式绕过缓存。
- 根据模块数、预计 token、图片数和内置费率提供生成前预算；未知费率、混合币种及缓存影响必须明确提示。

## 6. 文案、版本与审核

- 所有可见文案输出 `en/zh/de/fr/it/es`，语义保持一致，德语为效果图主文案。
- 可按实例局部重生成，也可输入统一要求后全局重生成。
- 修改或重生成形成版本记录；审核状态支持待审核、审核中、需修改和已通过。
- AI 自查覆盖真实性、绝对化声明、六语一致性、德语自然度、语法、长度、关键词堆砌和商标风险。
- 自查是辅助信号，不替代证据审核和母语人员终审。

## 7. 图片生成与局部重生

- 图片请求以真实产品参考图为基础，要求产品结构一致且不生成第三方 Logo、水印或不可验证徽章。
- 除白底首图外，先生成无文字构图，再由程序叠加德语文案，降低生成式文字错误。
- 可按实例局部重生；新 JPG 使用时间戳文件名，并同步刷新 Brief、Excel 和 ZIP。
- 局部重生支持画笔蒙版选区；产品结构锁定 Prompt 要求保持外形、轮组、拉杆、缝线、Logo位置、材质和颜色。
- 生成后计算产品参考图与 AI 图的感知结构相似度；低于用户阈值时写入警告，不冒充通过。
- 局部重生不删除旧图片，便于比较版本。
- 供应商不支持参考图、尺寸或同步返回结构时，应提示失败或降级为占位图，不伪装为成功结果。

## 8. 输出规范

图片模块表共 28 列：原 22 列之外，增加产品结构相似度、OCR 识别文字、六语回译检查、文案溢出检查、图片文字合规检查和 Amazon 规则预检。

`项目参数` 表记录通用信息、全部变体、竞品、关键词、模块实例顺序/Prompt及非敏感 AI 配置；存在历史版本时生成 `文案版本记录`，完成预检时生成 `Amazon规则预检`。图片统一输出 JPG，AI 图片另打包为 ZIP；项目、Brief、QA 与预检报告以 UTF-8 JSON 保存。

### 8.1 批量任务与规则库

- 批量 SKU 通过持久化项目 JSON 队列执行，单工作线程避免本机并发失控；支持暂停、继续、失败重试和应用重启后续跑。
- 内置规则库按 Amazon 站点代码和品类别名匹配，可导入本地 JSON 或从 HTTPS 地址更新；更新文件需通过 schema 校验。
- 导出前自动检查首图顺序/文字、图片尺寸、主图数量、目标站点语言覆盖、禁用声明及行李箱变体尺寸、登机/TSA 依据。
- 错误阻止导出，警告写入工作表和 JSON 供人工决策；规则库不能替代 Seller Central 的实时校验。

## 9. 异常与降级

- 缺少必填字段、未选择模块或主图首位不是白底首图：阻止完整生成。
- 启用 AI 图片但没有参考图或有效图片 Key：阻止生成。
- AI 文案功能没有有效文案 Key：明确提示且不破坏草稿。
- 单张图片 API 失败：生成占位图并继续，写入 `generation_warnings.txt`。
- 主供应商失败：先按设置重试，再按显式配置切换备用供应商；所有失败原因合并展示。
- OCR、回译或图片合规 AI 检查失败：保留本地结果、写入警告并继续，不伪造检查结论。
- Amazon 规则预检出现错误：阻止完整导出并显示规则 ID 与修复建议；警告不阻断。
- Excel 导入格式不可识别：停止导入并提示使用标准模板。
- 未启用 AI：仍可输出本地六语基础文案、设计说明和 Excel。

## 10. V2.4 验收标准

1. 文案和图片供应商可以独立选择、保存非敏感配置并切换。
2. Key 可通过环境变量或临时输入提供，任何导出文件均不含 Key。
3. 预置 OpenAI 与至少四种国内图片 API，并提供文案供应商和自定义配置。
4. 同一模块可以重复添加，每个实例具有唯一 ID 和独立 Prompt。
5. 重复实例可独立排序、改文案、审核、自查和局部重生，不互相覆盖。
6. 旧 V2 项目可迁移为实例结构并保留模块顺序。
7. 默认主图 9 张、高级 A+ 7 个，六语文案及 PC/移动尺寸完整。
8. 不配置 API 时仍能导出；配置后可生成或局部更新 JPG 参考图。
9. Excel、项目 JSON、Brief JSON 和 ZIP 的实例顺序及图片路径一致。
10. 模块选择页同时显示可添加与已选择列表，确认页可批量删除。
11. 真实连通测试、模型目录获取、费用预估、重试、限流、缓存和备用供应商切换均有可验证路径。
12. 批量队列可持久化、暂停/继续、失败重试并输出各 SKU 结果目录。
13. 蒙版局部重生、结构锁定与相似度结果能写回 Brief 和 Excel。
14. OCR、六语回译、溢出、图片文字合规与 Amazon 预检结果能写入 28 列需求表及独立报告。
15. 自动测试和 8 页 GUI 冒烟测试通过。
16. AI 页面不再显示协议、URL、Endpoint、Key 名称、临时 Key 或请求头输入框。
17. CUN.AI 可从供应商下拉选择，能通过 `GET /v1/models` 获取模型，并以 Python Chat Completions 调用所选模型。
18. 编辑 `resources/ai_providers.json` 后重启程序，可更新供应商连接参数而无需改动 UI 代码。
19. 变体可复制，选中编辑无需“更新选中”按钮即可在焦点变化、切换或导出前自动保存。
20. CUN.AI 同时出现在文案与图片供应商下拉中，图片模型从账户模型接口动态获取。
21. 图片合规 AI 检查紧邻文案溢出检查；局部重生不命中旧结果缓存。
